# 图片水印特征与修复调参参考

## 常见 AI 生成平台水印特征

| 平台 | 常见位置 | 形态 | 说明 |
|---|---|---|---|
| 即梦 AI(Jimeng) | 右下角 | 半透明白色/灰色文字 logo | 压在图内容上,文字加白色描边 |
| 可灵 AI(Kling) | 右下角 | 半透明小字 + 符号 | 深/浅色随图片明暗自适应 |
| Midjourney / Niji | 底部居左 | 灰色小字 "MJ·prompt 编号" | 附在底边,通常无半透明 |
| 通义万相 / 混元 | 右下或左下 | 半透明白色 logo | 画面内容之上 |
| 豆包 / Seedream | 右下角 | 半透明文字角标 | 尺寸小 |
| 社交平台下载 | 角落 | 用户名/平台 logo | 多为不透明实底 |

共性:
- **位置**:几乎都贴在四角(以右下、左下最常见),紧贴边缘或有 1~3% 留白。
- **透明度**:多数为半透明叠加(alpha ~ 40%~80%),盖住的背景仍然隐约可见。
- **尺寸**:一般占图片短边的 2%~10%,远小于画面主体。

## 检测脚本(detect_watermark.py)原理

- 对整图做**大核中值滤波**得到"背景估计"——水印这类小尺度文字/Logo 被抹平,画面大结构保留。
- `|原图 - 背景|` 得到"结构差图";在**四角 ROI(每边 24%)** 内做自适应阈值 + 膨胀连通,找出疑似水印块。
- 按"贴角程度 + 尺寸比例 + 结构强度"加权打分,输出候选与可视化标注图。

典型误报场景(需人工复核):
- 角部本身有真实内容(天空云层、建筑边缘、装饰元素)。
- 图片四边带深色渐晕/暗角(会形成大块 diff)。
- 图片内本就包含文字水印之外的小字。

**复核方式**:脚本可输出 `--visual 标注图`,执行 Agent 必须用 Read 打开该图核对每个框是否命中水印;漏检/误检时,直接看原图,估算水印的 (x, y, w, h) 后传给修复脚本 `--box`。

## 修复模式选择(inpaint_watermark.py)

- `--mode rect`:把整个水印矩形视为待修复区,inpainting 依据周边纹理"脑补"内容。
  - 适合:不透明实底水印、半透明色块、纹理不复杂的背景(天空、纯色、虚化背景)。
  - 缺点:复杂纹理上整块修复会产生轻微涂抹感。
- `--mode adaptive`:在矩形内用"局部背景中值差 + Otsu"仅切出文字/Logo 笔画,只修复笔画像素。
  - 适合:半透明白/黑文字水印叠加在较复杂但有规律的内容上,能保留更多原纹理。
  - 缺点:对颜色接近背景的半透明水印,笔画提取可能不完整,残留淡痕。
- `--mode both`(默认):同时输出两种结果与对比图,由执行 Agent / 用户肉眼选择更自然的一张。

## 参数调优

- 水印框略大于实际水印(留 2~4 像素余量)可避免边缘残影;脚本默认自动加 pad。
- 修复半径 `0.025 * 水印宽` 自动计算(clamp 3~20)。水印大时如结果过糊,可将框拆小、分多次修复。
- 大尺寸图片建议整图一次修复;若局部效果不理想,可把该区域裁出来单独修复后拼回(见 SKILL.md 降级路径)。

## 效果天花板与升级路径

本地 OpenCV inpaint 是"无模型、确定性"算法,复杂度有限。当出现以下情况时,应升级到 AI 补全路径(ImageGen 图生图 / 裁剪区域重绘):
- 水印覆盖了人脸、文字、标志性结构(本地修复无法"脑补"出可信细节)。
- 背景纹理高度复杂(密集树叶、毛发、织物),修复后有明显接缝或涂抹。
- 用户要求输出用于正式发布,肉眼几乎不可察觉。

## 合规提示

仅用于处理**自己拥有版权/已获授权**的图片(例如自产 AI 图片去平台角标)。不得用于去除他人作品或商业素材的版权标识。
